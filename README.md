# 🎾 nina_tennis

Система управления теннисными турнирами: сетки, расписание матчей, судейство в реальном времени, публичные табло и роли (админ / судья / зритель).

Монорепозиторий на npm workspaces: бэкенд (NestJS + MongoDB), фронтенд (Next.js) и общая библиотека типов и логики.

## 🚀 Возможности

### Турниры и сетки
- **Олимпийская сетка** (single elimination) с посевом игроков (snake-seeding)
- Визуализация сетки с соединительными линиями, зумом и **фильтром по раундам**
- BYE-слоты для неполных сеток
- Автоматическое продвижение победителей

### Судейство (live)
- **Рабочее место судьи**: подсчёт очков по правилам тенниса (0/15/30/40, deuce/advantage, тай-брейк до 7)
- **Быстрые клавиши**: `1`/`2` — очко, `Z` — отмена, `F` — завершить
- **Автосохранение** состояния (восстановление после рефреша страницы)
- Настройка подачи 🎾 и стороны корта
- **Публичное табло** `/m/:matchId` с автообновлением каждые 4 секунды, полноэкранный режим для ТВ/планшета

### Расписание и участники
- **Календарь игр турнира** — месячная сетка, клик по дню → список матчей с кортом и временем
- **Страница участника** — статистика (победы/поражения/винрейт/сеты), история матчей, запланированные игры
- **Профиль пользователя** с редактированием имени/email/пароля

### Система судей (referees)
- Админ генерирует **ссылку-приглашение** → человек регистрируется/входит по ней → становится судьёй турнира
- Судья может судить **любой матч** своего турнира
- У каждого матча видно, кто судил (история `judgedBy`)
- Таблица судей в админке с inline-редактированием

### Безопасность
- JWT-авторизация, ролевая модель (admin / referee / user)
- `RolesGuard` на всех записывающих эндпоинтах
- Безопасный JWT-секрет (в продакшене обязателен `JWT_SECRET`)

### Дизайн
- Тёмная/светлая тема (next-themes, без мигания при загрузке)
- Дизайн-система: переиспользуемые компоненты (Button, Card, StatusBadge, ScorePill и др.)

## ⚡ Быстрый старт

### 1. Установка зависимостей

Из корня репозитория:

```bash
npm run install:all
```

Это установит зависимости в корне, `apps/frontend`, `apps/backend` и `libs/shared`.

### 2. Настройка MongoDB

Убедитесь, что MongoDB запущена локально (`mongodb://localhost:27017`) или укажите `MONGO_URI` в `apps/backend/.env` на ваш Atlas-кластер.

### 3. Наполнение тестовыми данными (опционально)

```bash
npm run seed
```

Создаёт тестового администратора и демо-данные. ⚠️ Скачивает аватары (требуется интернет, 1–2 минуты).

**Учётная запись админа по умолчанию:**
- Первый зарегистрированный пользователь автоматически становится администратором.

### 4. Запуск в режиме разработки

```bash
npm run dev
```

Запускает бэкенд и фронтенд одновременно (через `concurrently`):
- **Фронтенд:** http://localhost:3100
- **Бэкенд (API):** http://localhost:3101

Откройте http://localhost:3100 в браузере.

## 👥 Роли и доступ

Система использует три роли пользователей:

| Роль | Описание | Доступ |
|------|----------|--------|
| **admin** | Администратор | Полный доступ: создание/редактирование турниров, групп, игроков, управление судьями, судейство любых матчей |
| **referee** | Судья | Судейство матчей турнира, к которому привязан. Доступ к рабочему месту судьи |
| **user** | Обычный пользователь | Просмотр публичных страниц, редактирование своего профиля |

**Логика ролей:**
- Первый зарегистрированный пользователь автоматически становится `admin`
- Роль `referee` присваивается при принятии приглашения от админа турнира
- Проверка ролей на бэкенде через `@Roles('admin')` / `@Roles('admin', 'referee')` декораторы + `RolesGuard`

## ⚖️ Система судей

### Как это работает

1. **Админ** открывает страницу турнира → «Судьи» → нажимает «Создать ссылку»
2. Получает многоразовую ссылку-приглашение вида `/invite/<token>`
3. Отправляет ссылку будущим судьям
4. **Судья** переходит по ссылке, регистрируется или входит → автоматически становится судьёй турнира (роль `referee`)
5. Судья открывает любой матч турнира → «Судить» → ведёт счёт
6. При сохранении судья фиксируется в матче (`refereeId` + история `judgedBy`)
7. Имя судьи отображается в карточке матча и расписании

### Проверка прав

Судья может судить **только матчи своего турнира**. Бэкенд проверяет: матч → группа → турнир → `tournament.referees.includes(userId)`. Чужому турниру — отказ (403).

## 📌 Примечания

- **Порты по умолчанию:** фронтенд `3100`, бэкенд `3101`, MongoDB `27017`
- **Polling для live-обновлений:** публичное табло опрашивает бэкенд каждые 4 секунды (WebSocket не используется — проще для деплоя)
- **Формат счёта:** строки вида `6-4 3-6 7-6(5)` (сет-сет, тай-брейк в скобках)
- **Полный снимок состояния** матча хранится в БД (`scoringState` + `pointHistory`) — позволяет точно восстановить судейство после рефреша
